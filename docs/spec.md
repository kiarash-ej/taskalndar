# Taskalndar — Spec v1

## هدف
وبسایت چندکاربره برای برنامه‌ریزی روزانه و تعیین هدف، با تقویم شمسی (جلالی) در سراسر
رابط کاربری، که پیشرفت هفتگی و درصد تغییر پیشرفت ماهانه (نسبت به ماه شمسی قبل) را
نمایش می‌دهد.

## کاربران و احراز هویت
- چندکاربره: هر کاربر با ایمیل/رمز عبور ثبت‌نام و وارد می‌شود (Supabase Auth).
- هر کاربر فقط داده‌های خودش را می‌بیند (Row Level Security در Postgres).

## مدل داده (Supabase / Postgres)

- **tasks** — کارهای روزانهٔ تعریف‌شده توسط کاربر (چک‌لیست)
  - `id`, `user_id`, `title`, `is_recurring` (روزانه تکرار می‌شود یا یک‌بار برای یک
    تاریخ خاص است), `created_at`, `archived_at`
- **task_completions** — ثبت انجام‌شدن یک کار در یک روز مشخص
  - `id`, `task_id`, `user_id`, `date` (تاریخ میلادی ذخیره می‌شود، UTC date)، `done`
- **goals** — هدف‌های عددی
  - `id`, `user_id`, `title`, `target_value`, `unit` (مثلاً کیلومتر، صفحه), `period`
    (`monthly` در v1), `created_at`, `archived_at`
  - `start_date` — اولین روز قابل ثبت/محاسبهٔ هدف، مستقل از زمان ایجاد رکورد
- **goal_logs** — ثبت پیشرفت یک هدف
  - `id`, `goal_id`, `user_id`, `date`, `amount`

تاریخ‌ها در دیتابیس به‌صورت میلادی (ISO date) ذخیره می‌شوند؛ تبدیل به شمسی فقط در لایهٔ
نمایش/محاسبه انجام می‌شود (با کتابخانهٔ `jalaali-js`).

مالک رکوردهای `task_completions` و `goal_logs` باید با مالک کار/هدف مرجع یکسان باشد؛
این شرط با کلید خارجی مرکب در دیتابیس برقرار است.
تغییر نوع کار از امروز یا روز انتخاب‌شدهٔ آینده اعمال می‌شود و نسخهٔ برنامهٔ قبلی تا
قبل از آن روز برای آمار باقی می‌ماند. ثبت انجام همان روز به نسخهٔ جدید منتقل می‌شود.
ثبت پیشرفت هدف قبل از `start_date` مجاز نیست؛ مایگریشن برای ثبت‌های قدیمیِ معتبر،
روز شروع را تا اولین ثبت عقب می‌برد. روز بایگانی هدف نیز در آمار حساب می‌شود.

## تقویم شمسی
- تمام تاریخ‌ها، نام روزها، نام ماه‌ها در رابط کاربری به شمسی نمایش داده می‌شوند.
- هفته از شنبه شروع می‌شود (استاندارد ایران).
- «هفته» و «ماه» برای محاسبات بر اساس تقویم جلالی تعریف می‌شوند، نه میلادی.

## محاسبهٔ پیشرفت
پیشرفت هر بازهٔ زمانی (هفته یا ماه) ترکیبی از دو معیار است:
1. **درصد تکمیل کارهای روزانه** = (تعداد کارهای انجام‌شده) / (تعداد کارهای موردانتظار)
   در آن بازه.
2. **درصد پیشرفت هدف‌ها** = میانگین (مقدار ثبت‌شده / هدف) روی همهٔ هدف‌های فعال آن بازه
   (حداکثر ۱۰۰٪ برای هر هدف).

**امتیاز ترکیبی پیشرفت** = میانگین ساده‌ی این دو درصد (۵۰٪–۵۰٪). اگر کاربر هیچ هدفی
تعریف نکرده باشد، فقط از معیار اول استفاده می‌شود.

- **پیشرفت هفتگی**: امتیاز ترکیبی برای هفتهٔ جاری (شنبه تا جمعهٔ شمسی جاری)، به همراه
  نمودار ۸ هفتهٔ اخیر.
- **درصد تغییر ماهانه**: `(امتیاز ماه جاری - امتیاز ماه قبل) / امتیاز ماه قبل × 100`.
  اگر ماه قبل امتیاز صفر داشته، به‌جای درصد بی‌نهایت، عبارت «شروع تازه» نمایش داده
  می‌شود.

## صفحات
1. **ورود/ثبت‌نام**
2. **داشبورد** — کارهای امروز (تیک زدن سریع)، امتیاز پیشرفت هفتهٔ جاری، نشان درصد
   تغییر نسبت به ماه قبل
3. **برنامهٔ روزانه** — مدیریت کارها (افزودن/ویرایش/حذف)، تقویم شمسی برای مرور روزهای
   دیگر
4. **هدف‌ها** — تعریف هدف عددی، ثبت پیشرفت روزانه/دوره‌ای
5. **آمار و پیشرفت** — نمودار پیشرفت هفتگی (۸ هفتهٔ اخیر)، مقایسهٔ ماه‌به‌ماه

- فرانت‌اند: Next.js (App Router) + React + Tailwind CSS
- بک‌اند/دیتابیس/احراز هویت: Supabase (Postgres + Auth + RLS)
- تبدیل تقویم: `jalaali-js`
- نمودارها: Recharts
- هاستینگ: Railway (سرویس Next.js متصل به همین ریپو)
- مخزن کد: `kiarash-ej/taskalndar` روی GitHub
